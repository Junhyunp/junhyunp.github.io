# junhyunp.github.io — 작업 인수인계

**작성 2026-08-14** · 이전 세션이 `CodersBlog.github.io` 경로에서 돌고 있어서, 이 저장소 경로로 옮겨 앉는 새 세션을 위해 남깁니다.

> `_` 로 시작하는 디렉토리라 Jekyll 빌드에서 제외됩니다 — 사이트에 노출되지 않습니다.
> 새 세션은 **이 파일을 먼저 읽고** 시작하면 됩니다. 아래 내용은 전부 실제로 확인·측정한 것입니다.

## 1. 이 블로그가 무엇인가

`https://junhyunp.github.io` — AI 를 다루는 **한국어 기술 블로그**. Jekyll + Chirpy 7.6.

편집 방향은 **세 축 + 하나**입니다.

| 축 | 카테고리 | 내용 |
|---|---|---|
| 개념 연재 | `Concept` | LLM·VLM 의 기본 용어와 개념 |
| 기술 리뷰 | `Tech` | 레포·도구·모델 뜯어보기 |
| 논문 리뷰 | `Research` | 최신 논문 |
| 소식 | `Trend` | SNS·블로그에서 포착한 이슈 |

**이 4개 외에 새 카테고리를 만들지 않습니다.** 새 주제가 나오면 카테고리가 아니라 **접두사**를 새로 만듭니다.

제목은 `[{접두사}] {한글 제목}` 형태입니다. 접두사는 `LLM` `Agent` `Model` `Prompt` `Tool` `IDE` `VLM` `Policy` 등, **출처가 아니라 대상의 분야**로 붙입니다. 같은 접두사가 여러 카테고리에 걸치는 건 의도된 것입니다 — `[Agent]` 가 `Tech` 와 `Research` 양쪽에 붙어 두 글이 한 주제임을 드러냅니다.

이전 블로그(`CodersBlog/CodersBlog.github.io`)는 **별개**입니다. 초기 글 일부만 복사해 왔고, 그쪽을 옮겨오거나 지우는 작업은 하지 않습니다.

### 독자층 — 2026-08-14 사용자 지시

**고수만 보는 블로그가 아닙니다.** 사용자가 명시적으로 말했습니다.

> 나는 이 블로그는 AI 고수들이 정보를 얻을 수 있는 것도 좋지만 초보자들이 보면서 성장할 수 있는 글들이 많았으면해

`Concept` 축이 원래 이 역할을 맡도록 설계돼 있었는데, 하네스 4부작을 포함해 `Research` 로 비중이 쏠려 있었습니다. **글감을 고를 때 `Concept` 을 의식적으로 섞습니다.** `topics.yml` 에 Concept 항목이 여럿 `todo` 로 남아 있습니다.

초보자용 글의 실무 지침:

- **용어를 처음 쓰는 자리에서 바로 풉니다.** 앞 글을 안 읽었어도 읽히게 하고, 관련 글은 링크로 잇습니다
- **추상적 정의가 아니라 구체적인 상황에서 출발합니다.** `rag-basics` 는 "사내 규정 200페이지에서 출장비 정산 기한 찾기" 하나로 글 전체를 관통시켰습니다
- **"잘 안 될 때 어디를 보나"** 같은 진입점을 넣습니다. `rag-basics` 의 검색/청킹/생성 3분기 진단이 그 예입니다
- **톤은 바꾸지 않습니다.** 검증 못 한 수치 금지·한계 명시는 그대로입니다 — 초보자일수록 과장된 설명에 크게 다칩니다. 설정 의존적인 벤치마크 숫자는 오히려 빼는 편이 낫습니다

## 2. 프론트매터 — 이 틀을 그대로 씁니다

```yaml
---
title: "[LLM] 한글 제목"
excerpt: "One-line English description by Junhyun"
description: "이 글이 무엇을 다루는지 한국어 1~2문장. 검색 결과에 그대로 노출됩니다."

categories:
    - Concept
tags:
    - [LLM, token, tokenizer]

toc: true
toc_sticky: true

date: 2026-08-14
last_modified_at: 2026-08-14

math: true
mermaid: true      # mermaid 블록을 쓸 때만
---
```

- `categories` 는 **항목 1개**, 4칸 들여쓰기
- `tags` 는 `- [a, b, c]` **한 줄** flow sequence (이 블로그 고유 관례)
- `description` **필수**. 없으면 jekyll-seo-tag 가 `excerpt`(영문)를 meta description 으로 내보내서, 한국어 검색어와 한 글자도 안 겹칩니다
- 파일명은 `_posts/YYYY-MM-DD-slug.md`, slug 는 영문 소문자+하이픈

> **permalink 가 `/posts/:title/` 이고 여기서 `:title` 은 파일명 slug 입니다.**
> 그래서 제목·카테고리를 나중에 바꿔도 URL 이 안 깨집니다. 반대로 **파일명을 바꾸면 URL 이 깨집니다.**

## 3. 글쓰기 스타일

- **한국어 존댓말** (`~합니다`, `~입니다`). 반말·개조식 금지
- 한 문장 = 한 문단. 문단 사이 빈 줄 하나
- 구조: 도입 2~3문장 → `##` 소제목 + 표/코드 → `## 정리` → `## 참고`
- `#`(h1)은 title 이 담당하므로 본문에 쓰지 않습니다
- **이모지 없음.** 과장 표현("혁명적", "완벽한") 금지
- **한계·주의점을 반드시 한 줄이라도 적습니다.** 이 블로그의 핵심 톤입니다
- 콜아웃: `{: .prompt-info }` `{: .prompt-tip }` `{: .prompt-warning }` — 인용문 바로 다음 줄에
- 분량은 60~100줄 선. 논문 2편 비교 같은 건 100줄까지 갑니다

### 문구 톤 — 사용자가 명시적으로 지적한 것

**"오글거리는" 표현을 싫어합니다.** 자기소개나 리드 문구에서 특히 그렇습니다. 담백하게 씁니다.

## 4. 절대 규칙

1. **사용자 승인 없이 push 하지 않습니다.** `main` push = GitHub Actions 즉시 배포입니다. 초안을 보여주고 승인받은 뒤에만 커밋·푸시합니다.
2. **날짜는 도구로 측정합니다.** 추정 금지. `date '+%Y-%m-%d'` 와 PowerShell `Get-Date -Format 'yyyy-MM-dd'` 교차 검증.
   ⚠️ Git Bash 에서 `TZ=Asia/Seoul` prefix 를 쓰지 않습니다 (환경 버그).
3. **논문은 arXiv 원문 페이지를 직접 엽니다.** 2차 소개글이 언급한 제목만 보고 인용하지 않습니다. 제목·저자·발표일·초록을 확인합니다.
4. **검증 못 한 수치는 쓰지 않습니다.** 벤치마크·스타 수·"N% 개선" 류는 1차 출처로 확인하거나 아예 뺍니다. 확인했으면 **기준 날짜를 명시**합니다.
5. **번역·복붙 금지.** 읽고 직접 확인한 뒤 우리 말로 재구성합니다. 원문 문장을 옮겨야 하면 인용부호 + 출처.
6. **기존 글의 본문을 임의로 수정하지 않습니다.** 오류처럼 보여도 의도일 수 있습니다. 보고만 하고 판단은 사용자에게 맡깁니다.
7. **Claude/Anthropic/모델 ID/API 요금이 글에 나오면 `claude-api` 스킬을 먼저 읽습니다.** 기억으로 쓰지 않습니다.
8. **실행 안 해본 코드를 "이렇게 하면 된다"고 쓰지 않습니다.**

### 출처 표기

본문 맨 아래 `## 참고` 에 모읍니다.

```markdown
## 참고

- [원문 제목](https://arxiv.org/abs/2608.13560) — 저자, 발표일 (YYYY-MM-DD 확인). 무엇을 가져왔는지 한 줄
- [이전 글 제목](/posts/slug/) — 어떻게 이어지는지
```

- 링크 텍스트는 **원 제목 그대로**
- **언제 확인했는지**를 괄호로 남깁니다
- SNS 를 통해 알게 된 것은 계정과 읽은 날짜를 밝히되, **사실 확인은 1차 출처에서 다시** 합니다

## 7. 커스터마이징한 것 — 깨뜨리지 말 것

Chirpy **starter 템플릿**(gem 기반)이라 테마 파일 대부분이 gem 안에 있고, 필요한 것만 골라 덮어썼습니다.

### `assets/css/jekyll-theme-chirpy.scss`

⚠️ **맨 위 테마 진입부를 절대 바꾸지 않습니다.**

```scss
@use 'main{% if jekyll.environment == 'production' %}.bundle{% endif %}';
```

`main.bundle` 에만 Bootstrap 이 들어 있어서, `.bundle` 을 떼면 **production 빌드에서 CSS 가 112KB → 72KB 로 줄고 레이아웃이 통째로 깨집니다.** 실제로 한 번 겪었습니다.

그 아래에 얹은 것들:
- Pretendard 폰트 변수
- PWA 업데이트 토스트를 오른쪽 아래로: `#notification.toast.show { left:auto; right:1rem; bottom:5.5rem; transform:none }`
- **데스크톱 사이드바 기본 숨김** + `[sidebar-display]` 속성으로 토글
- 메뉴 버튼을 상단 **최좌측**으로: `#sidebar-trigger { display:block; order:-2 }`, `#site-home { order:-1 }`
- 홈에서만 적용: `body:has(.home)` 으로 `#panel-wrapper` 와 `#breadcrumb` 숨김

### `_layouts/home.html`

직접 만든 홈 화면입니다. 구성은 **Hero(이름·리드·`CONCEPT · TECH · RESEARCH`·통계·소셜·네비) → 연도별 타임라인(Liquid 로 계산한 인라인 SVG) → 좌측 최근 글 + 우측 `site.data.reading` 패널** 순입니다.

`innei.in` 을 참고하되 **톤을 낮춘** 버전입니다. 화려하게 되돌리지 않습니다.

### `_includes/topbar.html`, `_includes/metadata-hook.html`

테마 원본을 복사해 최소 수정했습니다. **추가한 줄에 `<!-- ADDED -->` 표시**가 있으니 그것만 보면 됩니다. 각각 홈 링크, Pretendard + 네이버 인증 태그입니다.

### 아직 안 채운 것

`_config.yml` 의 `avatar:` 가 비어 있어 Hero 는 이니셜 원으로 대체 중입니다.

## 8. 발행 파이프라인

```bash
# 1. 상태 확인
git status --short          # clean 이어야 함
git pull

# 2. 날짜 측정 (교차 검증)
date '+%Y-%m-%d'
powershell.exe -Command "Get-Date -Format 'yyyy-MM-dd'"

# 3. 글 작성 후 렌더링 검증 — input:"GFM" 필수
ruby -rkramdown -rkramdown-parser-gfm -ryaml -rdate -e '...'

# 4. 사용자 승인 → 커밋·푸시
git add _posts/<파일> assets/img/post/<slug>/ .blog-automation/
git commit -m "post: <제목>"
git push

# 5. 배포 확인 — -R 반드시 명시
gh run list -R Junhyunp/junhyunp.github.io --limit 3 \
  --json workflowName,status,conclusion,displayTitle \
  --jq '.[] | "\(.workflowName)  \(.status)  \(.conclusion)  \(.displayTitle)"'

# 6. 배포 완료 후 IndexNow
ruby .blog-automation/indexnow.rb --latest
```

- **배포 전에 IndexNow 를 제출하지 않습니다.** 없는 URL 을 크롤러가 404 로 긁어갑니다
- IndexNow 정상 응답은 **200 또는 202**
- 키는 저장소 루트의 `<32자hex>.txt` **파일명 자체**입니다. 스크립트가 알아서 읽습니다
- **구글은 IndexNow 에 참여하지 않습니다.** 네이버·Bing 쪽만 자동화됩니다
