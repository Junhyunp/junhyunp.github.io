### 1. video-use — 코딩 에이전트로 영상 편집, 프레임 대신 전사+합성물로 "본다"

### 2. Judges as a Lifecycle — Netflix, LLM 심판을 4단계로 운영하기

**무엇**
Netflix 연구진(Kong, Tan, Gupta)이 대규모 추천 설명(매주 수십만 개의 쇼별 설명, 수백만 회원 대상)을 평가하는 LLM 심판을 "탄생→훈련→배포→모니터링" 4단계 생애주기로 관리하는 프레임워크를 제안했다고 한다. 훈련 단계에서 "Reasoning-Aligned Rubric Tuning(RART)"으로 채점 루브릭을 다듬고, 배포된 심판 하나가 품질 게이팅과 반성적 생성(reflective generation) 두 역할을 겸하며, 모니터링 단계는 사람 개입 루프로 드리프트를 감지해 재튜닝을 트리거한다고 소개된다.

**출처**
- [arXiv:2608.18300 — The Lifecycle of LLM-as-a-Judge for Large-Scale Recommendation Explanations](https://arxiv.org/abs/2608.18300) — WebSearch 로 초록 페이지 제목·저자·핵심 내용 확인. dair-ai/ML-Papers-of-the-Week GitHub 미러(주간 요약)와 개별 검색 결과 두 갈래가 서로 일치함을 교차 확인했다.
- 1차 출처: 위 arXiv 원문 — **egress 차단으로 열지 못함**(23일째 동일 증상).

**왜 쓸 만한가**
eval-driven-development 글이 다룬 "LLM 심판을 어떻게 믿을 것인가"라는 질문에 실제 프로덕션 운영 사례를 더한다. Zheng 외(2023)의 심판-사람 일치율 논의를 산업 배치 단계까지 확장하는 후속 소재가 된다.

**검증** — 미확인
원문에서 (1) RART 가 정확히 무엇을 어떻게 튜닝하는지, (2) 품질 게이팅과 반성적 생성을 한 심판이 겸하는 데서 오는 편향을 저자들이 어떻게 통제했는지, (3) "드리프트 감지" 기준이 구체적으로 무엇인지 반드시 확인해야 한다.

### 4. EvoMal — 스킬 라이브러리를 통해 스스로 퍼지는 코딩 에이전트 악성 스킬

**무엇**
스스로 진화하는(검색된 스킬을 모방해 새 도구를 짜는) 코딩 에이전트의 "자기중독(self-poisoning)" 취약점을 다룬 논문이라고 한다. 공유 스킬 라이브러리에 악성 스킬 하나를 심어두면 — 직접 호출하지 않아도 — 에이전트가 그것을 템플릿 삼아 모방해 새 스킬을 작성·저장·실행하게 된다는 것이다. EvoMal 공격은 페이로드를 "무해해 보이는 배너" 구조로 감싸 모방을 유도하고, 저작된 사본이 다시 라이브러리에 들어가 계속 모방되는 자기증식형 웜을 형성해 원래 심은 스킬을 제거해도 살아남는다고 한다. 6개 모델·153개 SWE-bench Verified 과제에서 공격 성공률 20.3~41.8%, 중독된 라이브러리는 심은 것보다 4.9~9.0배 많은 악성 스킬을 보유했고, 심은 스킬 제거 후에도 Qwen3 는 5라운드째 68%의 공격 성공률을 유지했다고(에이전트가 만든 사본이 남아서) 보도된다.

**출처**
- [arXiv:2608.25776 — EVOMAL: Self-Poisoning in Self-Evolving Coding Agents](https://arxiv.org/abs/2608.25776) — WebSearch 로 초록 페이지·alphaXiv 미러·제3자 리뷰(themoonlight.io)를 교차 확인했다.
- 1차 출처: 위 arXiv 원문 — **egress 차단으로 열지 못함**.

**왜 쓸 만한가**
08-29 ai-engineering-skills-map 글이 스스로 짚은 빈칸 — "에이전트 칸에 가드레일·적대적 입력·데이터 유출·거버넌스가 있는데 안전·거버넌스 쪽은 0편" — 에 정확히 들어맞는다. 08-31 SwarmWorld 리뷰와 같은 "다중 에이전트가 예상 밖으로 행동한다" 축이지만, 이번엔 구체적 공격 메커니즘과 수치를 갖춘 통제 실험이라 실증성이 더 높다.

**검증** — 미확인
(1) 153개 과제·6개 모델의 정확한 목록, (2) "배너" 구조가 정확히 어떤 형태인지, (3) 방어책의 정확한 수치와 그것이 이 논문 자체의 결과인지를 원문에서 확인해야 한다.

**주의**
WebSearch 결과 요약에 "counter-prompt 로 6.7%까지 낮췄다"는 문구가 섞여 나왔는데, 이것이 EvoMal 논문 자체의 수치인지 같이 검색된 다른 방어 논문의 수치인지 구분하지 못했다. 방어 효과를 인용하려면 반드시 원문에서 직접 확인해야 한다.

**분류안** — Research, prefix: Agent (거버넌스/안전 빈칸을 메우는 첫 논문 후보)

### 5. Prime Agent 공식 논문 — 08-10 리뷰한 그 도구의 근거가 나왔다 (하네스 연작 5편 후보)

**무엇**
2026-08-10 이 블로그가 GitHub 레포로 리뷰한 PrimeIntellect-ai/prime-agent 의 공식 논문으로 보이는 "Prime Agent: A Self-Improving RLM Harness"가 arXiv 에 올라왔다고 한다(2608.23552, 게시 약 2026-08-23). ARC-AGI-3 RHAE Best@1 을 30%→95.5%로 끌어올렸고, 장문맥 코딩·GPU 커널 생성·에뮬레이터 구성·nanoGPT 스피드런 등에서 기존/인기 하네스와 맞먹거나 앞선다고 밝힌다. 지속형 IPython REPL(Recursive Language Model 추상화), 하네스 실행 간 히스토리·메모리·스킬·프롬프트가 이어지는 Continual Harness 구조, 재귀적 서브에이전트 간 직접 통신을 핵심 요소로 든다.

**출처**
- [arXiv:2608.23552 — Prime Agent: A Self-Improving RLM Harness](https://arxiv.org/abs/2608.23552) — WebSearch 로 초록 페이지 제목·핵심 주장을 확인했고, Hugging Face Papers 미러·alphaXiv 미러·제3자 블로그 여럿이 같은 내용을 일관되게 전한다.
- 1차 출처: 위 arXiv 원문 — **egress 차단으로 열지 못함**. `huggingface.co/papers` 미러도 같은 이유로 접근 실패.

**왜 쓸 만한가**
이 블로그 하네스 연작(#34 Prime Agent 리뷰 → #35 Continual Harness 논문 → #36 AutoDesign/DarwinX → EvoHarness-RL → SwarmWorld)의 출발점이었던 도구에 마침내 공식 논문이 나온 것이다. 08-10 리뷰 당시는 레포·README 만 있었는데, 이제 "결과가 하네스 설계 때문이지 모델 능력 때문이 아니다"라는 핵심 주장을 검증할 수 있다.

**검증** — 미확인
(1) 30%→95.5% 수치의 정확한 실험 조건과 비교 대상 하네스 목록, (2) "결과가 모델이 아니라 하네스 프리미티브 때문"이라는 주장의 근거(어블레이션 실험 유무), (3) 08-10 리뷰 당시 확인한 레포 설명과 논문 서술이 정확히 일치하는지를 원문에서 대조해야 한다.

**주의**
없음.
