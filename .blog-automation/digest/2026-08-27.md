### 1. DeepSeek Harness — 모든 것을 플러그인으로 만든 하네스, 일주일 새 별 3만 4천 개

**무엇**
DeepSeek 이 공개한 `dsh`(DeepSeek Harness)는 "everything is a plugin"을 설계 원칙으로 삼은 에이전트 하네스다. 핵심 기능부터 확장 기능까지 전부 교체 가능한 플러그인으로 다루며, 기반 기술 Cordis 는 별도 문서("A Programming Paradigm for Spatiotemporal Composability")로 설계 철학을 설명한다. 아직 개발자 프리뷰 단계라 破괴적 변경이 예정돼 있다고 README 에 명시돼 있다. `npx @deepseek-ai/dsh web` 한 줄로 로컬 웹 UI(127.0.0.1:3080)를 띄운다.

**출처**
- [GitHub - deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) — 1차 출처. **직접 열어** README 전문(약 19.8만 stars, 최근 7일 +3.4만, MIT, master 브랜치 커밋 13,147개 이상, "개발자 프리뷰·breaking changes 예정" 고지)을 확인했다.
- 1차 출처(설계 철학 논문): "A Programming Paradigm for Spatiotemporal Composability" — README 가 언급하나 링크 대상 문서 자체는 이번에 직접 열어보지 않았다. 쓰기 전 확인 필요.

**왜 쓸 만한가**
이 블로그의 하네스 연작(#34 Prime Agent, #35 Continual Harness, #36 harness-search, harness-engineering)의 5번째가 될 수 있다. 앞의 편들이 "하네스를 어떻게 자동으로 고치나"에 초점을 맞췄다면, 이번 건은 애초에 하네스를 "전부 플러그인"으로 짜는 구조적 접근이라 각도가 다르다. 실제 대형 오픈소스 프로젝트(별 19만+)가 이 철학을 실물로 검증하고 있다는 점도 다른 편들(연구 논문 중심)과 대비된다.

**검증** — 확인됨

**주의**

### 2. 역전파 없이 에이전트를 학습시키다 — Agentic ESOpt

**무엇**
Agentic ESOpt(arXiv 2608.17310)는 역전파 대신 진화 전략(Evolution Strategies)으로 LLM 에이전트의 전체 파라미터를 파인튜닝하는 프레임워크다. 파라미터를 흔들어(perturbation) 완전한 에이전트 궤적을 실행해보고 보상으로 가중 평균해 업데이트하는 방식이라, 그래디언트·옵티마이저 상태·크리틱을 저장할 필요가 없어 추론 수준의 GPU 메모리만으로 학습이 된다. 15턴 스도쿠에서 동일 조건 GRPO 대비 12.5%p 앞섰고, Math/DocVQA 에서는 베이스 모델 대비 13.7점(GRPO 대비 8.3점) 개선을, WebArena-Lite 에서는 Qwen3.5-27B 가 스킬 없이도 29.47%→36.16%로 오른 결과를 제시한다.

**출처**
- [GitHub - zz1358m/Agentic-ESOpt](https://github.com/zz1358m/Agentic-ESOpt) — 1차 출처(논문 공식 코드 레포). **직접 열어** 위 수치 전부와 별 52개·MIT 라이선스, HF 논문 페이지 링크(huggingface.co/papers/2608.17310)를 확인했다.
- 논문: arXiv 2608.17310 — **arxiv.org 원문은 EGRESS_BLOCKED 로 못 열었다.** 위 수치는 레포 README 에 정리된 것을 그대로 옮겼다.

**왜 쓸 만한가**
하네스 연작과 인접하지만 축이 다르다 — "하네스 구조"가 아니라 "학습 방법"(RL 대신 진화 전략)이다. Continual Harness(#35)의 process-reward co-learning 과 대조하는 각도로 쓸 수 있다. Research 카테고리에 "어떻게 학습시키나"라는 새 결을 더한다.

**검증** — 확인됨(레포 기준)
공식 코드 레포를 직접 열어 수치를 확인했다. arXiv 원문 자체는 못 열었으므로, 실험 조건(GRPO 베이스라인 하이퍼파라미터, "동일 조건"의 정의)은 쓰기 전 원문에서 재확인해야 한다.
