### 1. Wrapture — AI 어시스턴트가 처음부터 끝까지 짠 Python 라이브러리

**출처**

### 2. Scroll — 컨텍스트 관리를 스키마가 아니라 코드로

**무엇**
Alibaba 연구진이 낸 메모리/컨텍스트 관리 시스템. 세션마다 append-only 이벤트 로그 + 샌드박스 Python 커널을 두고, 도구 출력·검색된 이력·파생 상태를 타입 있는 변수로 유지한다. 모델이 코드를 짜서 이 상태를 검색·가공하고, 명시적으로 print 된 결과만 프롬프트(작업 뷰)로 들어온다. 컨텍스트 예산이 차면 오래된 구간을 몰아내되(evict) 완전히 버리지 않고, 인덱스로 언제든 원 이벤트 로그의 정확한 위치로 되돌아갈 수 있게 한다. Qwen3.8-Max 로 LongMemEval_S 94.8%, BEAM_10M 73.1%(기존 최고 대비 +5.1점), LOCA_256K 86.7%를 보고했다고 한다.

### 3. 압축이 지우는 것 — CLAUDE.md 규칙이 첫 희생자인 이유

**무엇**
프로덕션 에이전트 설정 20개를 대상으로, 컨텍스트 압축(compaction)이 실제로 무엇을 파괴하는지 측정한 논문. AGENTS.md·CLAUDE.md 에 적어둔 안전 규칙과 일반 대화 로그가 같은 압축률로 뭉뚱그려지는데, 정확한 문구가 살아있어야 하는 건 규칙 쪽뿐이라는 게 핵심 문제의식이다. Claude Code compact(Sonnet 4.6 기준)는 한 번 압축에 안전 규칙의 53%만 보존하고, 다섯 번째 압축 후엔 10%까지 떨어진다고 한다. 대안으로 지식베이스를 유형별로 분류해 유형마다 다른 보존 정책을 쓰는 "Knowledge Triage"를 제안, 압축률마다 안전 규칙을 2~4배 더 많이 보존하면서 5회 압축 후에도 96% 재현율을 유지했다고 주장한다.

**출처**
- [arXiv:2608.22752 — What Compaction Destroys](https://arxiv.org/abs/2608.22752) — dair-ai GitHub 미러(2차)로 초록·수치 확인.
- 1차 출처: 위 arXiv 원문 — **egress 차단으로 열지 못함**.

**왜 쓸 만한가**
큐에 아직 todo 로 남아있는 "CLAUDE.md로 AI에게 프로젝트 규칙 알려주기"(id 22) 글과 정면으로 만난다 — "규칙 파일을 왜 쓰는가"만이 아니라 "그 규칙이 긴 세션에서 실제로 얼마나 안 지켜지는가"까지 다룰 근거가 된다. context-window 글의 "긴 대화에서 앞부분을 잊는다"는 설명을 안전 규칙이라는 구체적 사례로 좁힌 후속이기도 하다.

**검증** — 미확인
(1) "안전 규칙 53%→10%"가 정확히 무엇을 세는 지표인지(문구 그대로 보존 vs 의미 보존), (2) Knowledge Triage 세 연산자(압축·분할·검색)의 구체적 작동 방식, (3) 20개 프로덕션 설정의 출처(자체 수집인지 공개 데이터인지)를 원문에서 확인해야 한다.
