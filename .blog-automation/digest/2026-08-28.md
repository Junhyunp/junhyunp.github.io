### 1. LangChain deepagents — "배터리 포함" 에이전트 하네스

**무엇**
LangChain 이 낸 `deepagents` 는 LangGraph·`create_agent` 위에 얹은 "옵션이 있는(opinionated)" 에이전트 하네스다. 장기·다단계 작업에 맞춘 기본값을 제공하면서도 모델·백엔드는 자유롭게 바꿀 수 있게 짰다. 서브에이전트(격리된 컨텍스트로 작업 위임), 파일시스템 연동, 자동 요약을 통한 컨텍스트 관리, 샌드박스 내 셸 실행, 세션을 넘나드는 영속 메모리, 툴 호출을 사람이 승인·수정하는 human-in-the-loop, 온디맨드로 불러 쓰는 스킬 시스템, MCP 서버 연동까지 한 데 묶었다.

**출처**
- [GitHub - langchain-ai/deepagents](https://github.com/langchain-ai/deepagents) — 1차 출처(공식 레포). **직접 열어** 위 아키텍처 서술 전부와 별 28.6k, MIT 라이선스를 확인했다.

**왜 쓸 만한가**
이 블로그의 하네스 연작(#34 Prime Agent, #35 Continual Harness, #36 harness-search·harness-engineering)에 자연스럽게 이어진다. 앞의 편들이 "하네스를 자동으로 고치는 법"·"논문 단위 설계"였다면, 이번 건은 실제로 널리 쓰이는 프레임워크(LangGraph 위에 얹힘, 28.6k stars)가 그 설계를 표준 컴포넌트 목록(서브에이전트/파일시스템/컨텍스트 관리/휴먼인더루프)으로 정리해 보여준다는 점이 다르다.

**검증** — 확인됨
공식 GitHub 레포를 직접 열어 핵심 아키텍처 서술과 별 수·라이선스를 확인했다. 다만 README 에 "최근 변경사항"이 구체적으로 적혀 있지 않아, 쓰기 전에 릴리스 노트·CHANGELOG 를 별도로 확인할 필요가 있다.

### 2. Cloudflare Computer — 에이전트에게 컴퓨터 한 대를 통째로

**무엇**

README 는 이를 "에이전트에게 컴퓨터를 쥐여준다"고 설명한다. SQLite 기반 영속 상태, 지연 연결 방식의 여러 실행 백엔드, MCP 연동 예제까지 포함한다. 다만 **README 가 명시적으로 "프리뷰 단계이며 실험·프로토타입용, 프로덕션 비권장"** 이라고 밝히고 있다.

**출처**
- [GitHub - cloudflare/computer](https://github.com/cloudflare/computer) — 1차 출처(공식 레포). **직접 열어** 위 아키텍처·상태 고지·별 8.8k·MIT 라이선스를 확인했다.

**왜 쓸 만한가**

### 4. VoiceMem — 음성 언어모델을 위한 "좌뇌·우뇌" 스트리밍 메모리

**무엇**
VoiceMem(arXiv 2608.26005, 2026-08-26 제출, 난양공대·싱가포르국립대·칭화대·홍콩중문대 등 공저)은 음성 언어모델(SLM)을 위한 메모리 아키텍처다. 정보를 담당하는 "좌뇌"와 감정·페르소나를 담당하는 "우뇌"를 병렬로 두고, 스트리밍 방식으로 메모리를 읽고 쓴다. WebSearch 로 확보한 요약에 따르면 top-5 검색에서 좌뇌가 Mem0(top-200 기준) 대비 30점 가까이 앞섰고, 우뇌는 3개 페르소나 벤치마크에서 기존 최고 대비 4.29점 개선했으며, 검색 자체는 134ms 만에 끝난다고 주장한다.

**출처**
- [arXiv:2608.26005 VoiceMem: Streaming Dual-Brain Memory for Real-Time Interaction](https://arxiv.org/abs/2608.26005) — **arxiv.org 는 EGRESS_BLOCKED 로 이번 스윕에서 열지 못했다.** 위 수치와 저자 정보는 WebSearch 요약 스니펫에서만 확보했다.
- 1차 출처: 존재는 확인(arXiv ID·저자·제출일 확인)했으나 원문 접근은 실패. 공식 코드 레포는 이번 검색에서 찾지 못했다.

**왜 쓸 만한가**
이 블로그가 아직 다루지 않은 "음성/실시간 대화 에이전트의 메모리" 축이다. 기존 Concept 편들(임베딩·RAG·컨텍스트 윈도우)이 텍스트 중심이었던 것과 달리, 실시간 지연(134ms)이라는 제약이 메모리 설계에 어떻게 영향을 주는지 보여줄 수 있는 사례.

**검증** — 미확인
arXiv 원문을 직접 열지 못했다. 쓰기 전에 반드시: (1) arxiv.org 원문에서 위 수치(30점, 4.29점, 134ms)의 정확한 정의와 비교 조건을 확인하고, (2) 공식 코드/데모 공개 여부를 다시 검색하고, (3) Mem0 비교가 동일 조건인지 확인해야 한다.

**주의**
1차 출처를 못 연 상태로 수치만 옮긴 것이다. 검증 전에는 수치를 단정적으로 쓰지 말 것.

**분류안** — Research, prefix: Voice (신규 prefix 제안 — 기존 LLM/VLM/Agent 어디에도 깔끔히 안 들어맞음)
