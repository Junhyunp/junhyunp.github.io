### 1. Headlong — 요청-응답을 버리고 "혼잣말 루프"로 도는 하네스

**무엇**
Laude Institute 가 공개한 Headlong 은 1만 줄 미만의 Bash 로 짠 "마이크로 하네스"다. 대부분의 에이전트 프레임워크가 요청이 오면 응답하는 반응형 구조인 것과 달리, Headlong 은 외부 입력이 없을 때도 사람의 "혼잣말(inner monologue)"처럼 에이전트가 스스로 사고를 이어가며 우선순위를 정하게 한다. 데모 에이전트 "Audel"은 프롬프트 없이 스스로 프로젝트를 시작하고 자기 코드를 디버깅했으며, 유휴 시 지수 백오프로 시간당 약 $1~2 수준의 비용으로 돈다고 소개한다. Docker 샌드박싱, 궤적(trajectory) 기반 전체 기억, fork-test-merge 방식의 자기개선 워크플로우도 갖췄다.

**출처**
- [GitHub - laude-institute/headlong](https://github.com/laude-institute/headlong) — 1차 출처. **직접 열어** README 전문(645 stars, 50 forks, Apache 2.0, "Of bash, by bash, for bash; it's shells all the way down.")을 확인했다.
- [Headlong: a microharness for persistent agents](https://www.laude.org/updates/headlong-a-microharness-for-persistent-agents) — Laude Institute 공식 발표 글. **laude.org 는 EGRESS_BLOCKED 로 못 열었다.** WebSearch 스니펫으로만 비용($1~2/h)·데모(Audel) 서술을 확인.

**왜 쓸 만한가**
이 블로그의 하네스 연작(#34 Prime Agent, #35 Continual Harness, #36 harness-search, harness-engineering, 그리고 어제 후보였던 ARIS)의 다음 편이 될 수 있다. 다른 편들이 "하네스를 어떻게 자동으로 고치나"에 초점을 맞췄다면, 이번 건은 "요청-응답 자체를 버린다"는 더 근본적인 구조 변경이라 각도가 다르다.

**검증** — 확인됨(레포 기준)
공식 GitHub 레포는 직접 열어 확인했다. 다만 공식 발표 블로그(laude.org)는 접근이 막혀 비용·데모 서술은 2차 스니펫에 의존했다 — 쓰기 전 캐시나 우회 경로로 laude.org 원문을 한 번 더 확인해야 한다.

### 2. 스킬은 지식이 아니라 "판박이"였다 — 스킬 100개 넘으면 정밀도 3.3%

**무엇**
"Demystifying Agent Skills: Why They Work-Until They Don't"(arXiv 2608.14036, 2026-08-14)는 에이전트 스킬이 실제로 왜 작동하는지를 실증 분석했다. 핵심 발견: 스킬이 성능을 올리는 이유의 65.7%는 "절차적 고정(procedural anchoring)"이고 명시적 지식 주입은 4.5%에 불과했다 — 즉 스킬은 모르는 지식을 알려주는 게 아니라 행동을 고정시키는 쪽에 가깝다. 같은 조건에서 스킬은 Workflow Memory 대비 61.9% vs 55.9%로 6.06%p 앞섰다. 그리고 가장 뼈아픈 수치: 스킬 풀이 5개에서 100개로 늘면 임베딩 기반 검색 정확도는 88.3%→76.9%로 완만히 떨어지지만, 실제 런타임에서 맞는 스킬을 골라 쓰는 정밀도는 29.6%→3.3%로 급락한다.

**출처**
- [GitHub - zhiyuanjiang04/demystify-agent-skills](https://github.com/zhiyuanjiang04/demystify-agent-skills) — 1차 출처(논문 프로젝트 레포). **직접 열어** 저자 전원, arXiv 링크, 위 수치 전부(61.9%/55.9%, 65.7%/4.5%, 88.3%→76.9%, 29.6%→3.3%, invocation 실패율 10.0% vs 0.8%/0.4%)를 README 에서 확인했다.
- 논문: arXiv 2608.14036 — **arxiv.org 원문은 EGRESS_BLOCKED 로 못 열었다.** 위 수치는 레포 README 에 정리된 것을 그대로 옮겼다.

**왜 쓸 만한가**
바로 어제(2026-08-24) 발행한 claude-code-skills(#47)의 직접 후속이 될 수 있다. 그 글은 "스킬 폴더를 몇 개 쓰나"를 개인 세트(10개)에 대본 것이었는데, 이 논문은 그 축을 정면으로 뒷받침한다 — 스킬 풀이 커질수록 "맞는 것 고르기"가 왜 어려워지는지 정량적 근거가 된다.

**검증** — 확인됨(레포 기준)
논문 프로젝트 공식 GitHub 레포를 직접 열어 수치를 확인했다. 다만 arXiv 원문 자체는 못 열었으므로, 실험 설계(평가 태스크 종류, "invocation 실패"의 정의, 61.9%/55.9% 비교의 통제 조건)는 쓰기 전 원문에서 재확인해야 한다.

### 3. ASI-Bench — 가이드를 걷어내자 점수가 반토막났다

**무엇**
ASI-Bench(arXiv 2608.17271, 2026-08-18)는 AI 가 사람의 방법론 지도 없이 얼마나 스스로 연구를 진행할 수 있는지를 재는 벤치마크다. 11개 과학 분야에 걸친 60개 프로젝트급 과제를 4단계 조건(B1: 방법 전체 안내 / B2: 방법만 지목 / B3: 목표·데이터만 제공 / B4: B3 에 무관한 정보까지 추가)으로 나눠, 같은 과제에서 안내를 점점 걷어내며 성능을 잰다. 18개 최신 에이전트-모델 조합을 돌린 결과 평균 점수는 방법 전체 안내 시 50.91점에서, 방법만 지목하면 29.10점, 스스로 방법을 정해야 하면 26.62점으로 떨어졌다. 구축에는 40명 이상의 전문가와 3만 1천 시간 이상이 들었다고 명시한다.

**출처**
- [GitHub - apexin-ai/ASI-Bench](https://github.com/apexin-ai/ASI-Bench) — 1차 출처(공식 벤치마크 레포). **직접 열어** 184 stars, 60개 과제·11개 분야·B1~B4 조건 구성, 40명+/3.1만 시간 구축 비용, arXiv 링크, Tsinghua·MIT·Harvard·CMU 등 소속을 확인했다.
- 논문: arXiv 2608.17271 — **arxiv.org 원문은 EGRESS_BLOCKED 로 못 열었다.** 50.91→29.10→26.62 점수 흐름은 WebSearch 스니펫에서 나온 것이라 레포 README 로 재확인 못 했다 — 원문 표를 직접 봐야 한다.

**왜 쓸 만한가**
하네스 연작(#34~36, harness-engineering)이 "에이전트가 스스로를 고친다"는 축이었다면, 이 벤치마크는 "에이전트가 스스로 방법을 고른다"는 인접하지만 다른 질문을 던진다. 이 블로그가 아직 다루지 않은 "AI 가 어디까지 자율적인가를 어떻게 측정하나"라는 평가(eval) 축의 도입점이 될 수 있다.

**검증** — 확인됨(레포 기준) / 미확인(점수 수치)
공식 레포의 구조·구축 규모는 직접 확인했다. 다만 핵심 수치인 50.91→29.10→26.62 점수 하락은 레포 README 에서 재확인하지 못했고 WebSearch 스니펫에만 의존했다 — arXiv 원문이나 공식 리더보드(asibench.apexin.ai)에서 반드시 재확인해야 한다.
